# .github

계정의 기본(default) 커뮤니티 헬스 파일 저장소입니다. 여기에 둔 이슈·Pull Request 템플릿은 자체 템플릿이 없는 이 계정의 모든 저장소에 자동으로 적용됩니다.

## 제공 템플릿

| 구분 | 파일 | 운영 상태 |
| --- | --- | --- |
| 버그 신고 | `.github/ISSUE_TEMPLATE/bug_report.yml` | 사용 중 |
| 기능 제안 | `.github/ISSUE_TEMPLATE/feature_request.yml` | 필요할 때 활성화 예정 |
| 개선 제안 | `.github/ISSUE_TEMPLATE/improvement.yml` | 필요할 때 활성화 예정 |
| 질문·기타 | `.github/ISSUE_TEMPLATE/question.yml` | 사용 중 |
| Pull Request | `.github/PULL_REQUEST_TEMPLATE.md` | 사용 중 |

기능 및 개선 제안 템플릿 파일은 저장소에 포함되어 있지만, 현재 이슈 운영에서는 버그 신고와 질문·기타 템플릿만 사용합니다. 빈 이슈 작성은 비활성화되어 있으므로, 세 템플릿에 해당하지 않는 내용은 질문·기타 템플릿으로 등록합니다.

## 파일 구조

```text
.github/
├── ISSUE_TEMPLATE/
│   ├── bug_report.yml
│   ├── config.yml
│   ├── feature_request.yml
│   ├── improvement.yml
│   └── question.yml
└── PULL_REQUEST_TEMPLATE.md
```

## 이슈 운영 규칙

### 템플릿과 제목

- 버그는 반드시 `버그 신고` 템플릿으로 등록합니다.
- 버그 제목의 `[Bug] ` 접두어를 유지합니다.
- 기능 제안 템플릿은 필요해지면 활성화합니다.
- 기능 제안 템플릿을 사용할 때는 제목의 `[Feature] ` 접두어를 유지합니다.

### 라벨

초기 운영에서는 다음 라벨을 사용합니다.

- `bug`: 버그 신고
- `enhancement`: 기능 제안
- `refactor`: 개선·리팩터링 제안
- `question`: 질문 및 기타 논의

`priority:*` 형식의 우선순위 라벨은 운영 상황을 확인한 뒤 추가합니다.

### 버그 신고 작성 규칙

다음 항목은 반드시 작성합니다.

- 문제 설명
- 재현 절차
- 예상 결과
- 실제 결과
- 실행 환경

이슈를 등록하기 전에 다음 사항을 확인합니다.

- 유사한 이슈가 이미 등록되어 있는지 검색합니다.
- 계정, 비밀번호, API 토큰 등 민감정보가 포함되지 않았는지 확인합니다.

필요하면 원인 파악에 도움이 되는 로그와 스크린샷을 추가합니다. 로그를 첨부할 때도 민감정보를 제거해야 합니다.

### Triage와 종료

- 스프린트 시작 전에 열린 이슈를 확인합니다.
- 개발자끼리 이슈의 처리 순서를 논의합니다.
- 이슈를 닫기 전에 실제 수정 여부를 확인합니다.
- 수정된 동작이 기대한 결과와 일치하는지 검증합니다.

## 적용 방식

- 자체 템플릿이 없는 저장소는 이 저장소의 템플릿을 자동으로 상속합니다. 별도 복사가 필요 없습니다.
- 저장소 성격에 맞는 커스터마이징이 필요한 경우에만 이 저장소의 템플릿을 해당 저장소의 `.github` 디렉터리로 복사해 수정합니다. 개별 저장소의 템플릿이 기본 템플릿보다 우선합니다.
- 템플릿을 사용하는 저장소에는 `bug`, `enhancement`, `refactor`, `question` 라벨이 있는지 확인합니다. 라벨이 없으면 이슈 등록 시 라벨이 적용되지 않습니다.
- 기본 상속이 동작하는지 확인하려면 다른 저장소의 새 이슈 작성 화면에서 템플릿 목록이 표시되는지 확인합니다.

## 운영 방침 변경

기능 제안 템플릿, 개선 제안 템플릿, 우선순위 라벨은 실제 운영 필요성이 확인되면 활성화하거나 추가합니다. 운영 규칙이 변경되면 템플릿과 이 문서를 함께 갱신합니다.
